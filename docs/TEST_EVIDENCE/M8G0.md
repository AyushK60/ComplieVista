Reproduced environment facts the launcher is built on (each verified live):

1. WSL 3.0.3.0 tears down `wsl.exe` session process trees — plain
   `nohup … &` and `setsid … &` daemons die with the launcher;
   `setsid -f` (double fork) survives.
2. `wsl.exe -- sh -c "…"` re-wraps via the login shell and strips quoting
   (`$!` came back empty); `wsl.exe -e` execv's directly and works.
3. Windows-side directory caching on `/mnt/e` (9P) can hide fresh pid files
   from `Test-Path`; the launcher polls through WSL.
4. A vite listener's process group is its npm leader's pid; Stop reads the
   real pgid from `/proc/<pid>/stat` (reproduced: assuming pgid==pid failed
   to stop the group).

## 6. Regression found and fixed during verification (in-scope, honest record)

The framed-channel harness initially DEADLOCKED and amplified events:
CPython fires trace events for frames created while the tracer itself runs
(`emit → json.dumps → …`), and the harness's own
traceback/linecache/re bookkeeping was traced. A module-level
ZeroDivisionError (ERR-RUNTIME fixture) flooded 5000+ events and deadlocked
the channel writer (container SIGKILL, exit 137). Diagnosed with a
faulthandler thread dump. Fixes: tracer re-entrancy guard + harness-globals
frame skip; tracing ends the moment `exec` returns/raises; channel writes are
non-blocking with honest drop accounting (`channel_frames_dropped`; drops
force integrity SUSPECT). Post-fix: 17 events, honest
`ZeroDivisionError` exception event, exit 0.

A second defect was found by the failing suite itself:
`run_capped`'s pump lambdas hardcoded `STDOUT_CAP`, ignoring the new
`stdout_cap` parameter — framed streams were cut at 1 MB, corrupting the
final frame. Wired through; both affected tests green.

## 8. Limitations (explicit)

- Reboot-level launcher test not performed (manual step documented).
- Trace trust: an untrusted target shares the pid/uid domain; a
  `/proc/self/fd` scan could in principle reach the observer channel fd —
  labeled `UNTRUSTED_TARGET` per run; full trust-domain separation is future
  work before any public exposure (ADR-0011).
- `wsl.exe` session teardown behavior is specific to WSL 3.0.3.0 on this
  machine; the launcher fails loudly (no false success) if daemons die.
