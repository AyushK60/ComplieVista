### Vite watching on /mnt/e — measured

- Without polling: 0 config-change detections, 0 HMR events (inotify does not
  propagate over 9P). Vite restart was required manually.
- With `server.watch.usePolling, interval 300` (set in `frontend/vite.config.ts`):
  `hmr update /src/App.tsx` logged within one 250 ms probe poll of the edit
  (sub-second), with a connected browser client.
- Note: Vite only logs HMR events when a client is attached — a client-less probe
  falsely suggests the watcher is dead.
- `npm install` on /mnt/e with WSL Node: 18.18 s wall clock (log excerpt:
  `4.08user 2.42system 0:18.18elapsed`).

## Deliverable F — Docker feasibility (NOT a safety claim)

```
python3 sandbox/feasibility_m0.py
Docker feasibility: server=29.9.2
  python_curated_deterministic   pass=True exit=0 out='total=28\n' cleanup_ok=True  249ms
  c_curated_deterministic        pass=True exit=0 out='total=28\n' cleanup_ok=True  215ms
  python_infinite_loop_timeout   pass=True exit=-1 out=''          cleanup_ok=True 20095ms
OVERALL: PASS
```

Baseline accepted by Docker 29.9.2: `--network none --read-only --tmpfs /tmp:rw,size=4m,noexec
--cap-drop ALL --security-opt no-new-privileges --user 1000:1000 --memory 128m --cpus 0.5
--pids-limit 64 --ulimit fsize=… ` + read-only bind of a staged job dir + `--rm`.
Image identities recorded as RepoDigests in `evidence/m0/docker/manifest.json`
(ubuntu:24.04, python:3.12-slim).

**Finding:** an external `timeout` that kills the `docker run` CLI leaves the
container running (`--rm` never fires). The orchestrator must enforce cleanup itself
(`docker rm -f` + inspect-verify) — implemented and tested; recorded in ADR-0003.

## Known issues / limitations

1. M0 does **not** prove a secure sandbox; adversarial validation is the M4 gate.
2. GDB/ptrace inside execution containers: declared UNSUPPORTED (ADR-0003).
3. Windows port 8000 conflict (unrelated process) → dev backend on 8123.
4. Vite on /mnt/e requires polling; CPU cost bounded by 300 ms interval on a small tree.
5. Full-page browser screenshots from the in-app browser showed a stitching artifact
   (content duplicated below the fold); DOM snapshot + viewport capture are ground truth.
6. Staging copy overhead measured at ~4× direct /mnt/e read on a tiny tree (83 ms vs
   21 ms) — acceptable; larger-tree benchmarks belong to later milestones.
